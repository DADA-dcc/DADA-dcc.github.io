1) 它是干什么的（说白了）

一句话：给 AI 编程助手装一套"职业习惯"。

你随口说"帮我做个 X"，普通 AI 会立刻开始写代码；装了 Superpowers 的 AI 会先反过来问你："你到底想解决什么问题？" 问清楚后，先给你一份设计说明（一小段一小段给你看），你点头了才出实施计划，然后才动手写，而且每写一段都要先写测试、看它失败、再写代码、看它通过。

它不是"一个工具"，而是一组技能（skills） + 一段开场指令：让你用的 AI（Claude Code、Codex、Cursor、Gemini CLI……）在合适的时机自动加载对应的技能。

3) 核心机制（它怎么做到"自动"）

A. 技能是"带触发条件的行为规范" 每个技能就是一份 Markdown：什么情况该用、按什么步骤做、做到什么标准。AI 读到就会照着做——不是靠你每次提醒。

B. 一个"总开关"技能 using-superpowers 会被装进 harness 的启动流程，它的描述会提示模型"开场就加载我"，于是后面的技能就能按阶段被触发。

C. 把"开发"拆成固定流水线 1. brainstorming：问清你要什么 → 复述给你确认 2. using-git-worktrees：开独立分支，跑一遍测试确认基线干净 3. writing-plans：拆成 2-5 分钟的小任务，每个任务写清文件路径、代码、验证步骤 4. subagent-driven-development：每个任务派一个子代理去做，做完立刻审查（先查是否符合规格，再查代码质量） 5. test-driven-development：强制 RED-GREEN-REFACTOR（先写失败的测试→最小实现→测试通过→提交） 6. requesting-code-review：收尾前自查清单

D. 理念写死在技能里 TDD 优先、系统化而非拍脑袋、以"降低复杂度"为目标、先验证再宣布完成。

4) 一次完整使用

以 Claude Code 为例（其它 harness 类似，README 里有逐家命令）：

/plugin install superpowers@claude-plugins-official

或从它自己的市场装：

/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

装完你只要正常提需求，例如"给这个仓库加一个导出 CSV 的按钮"，它会： 先问你用途 → 给你设计 → 你确认 → 出计划 → 派子代理逐条实现 → 每条都跑测试 → 最后自查。

5) 它比同类强在哪

  1. 不是提示词合集，是方法论：从需求澄清到合并分支，全流程都有对应技能；
  2. 子代理编排是真的：subagent-driven-development + dispatching-parallel-agents，把"一个 AI 干完"变成"多个 AI 分工 + 互相审查"；
  3. 强制 TDD：技能里直接规定"测试没过不许写实现"，把纪律写进流程；
  4. 跨 harness 覆盖极广：15+ 种客户端都有安装方式，换工具不用重学；
  5. 可扩展：writing-skills 教你怎么写新技能，还带测试方法。
