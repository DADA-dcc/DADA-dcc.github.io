2) 逐项目要点回顾

craft-anything（2026-11-15）

  • 本质：三层结构——egui 桌面 App / CLI / MCP server 三个入口，共用同一个纯 Rust 引擎（约 320 个工具，300 在内核），引擎自带解析器/反汇编器/反编译器，Ghidra 可选增强。
  • 四步流水线：Study(取证研究) → Build(编码智能体生成) → Check(与原对象逐项比对) → Ready(预览/迭代)；比对是硬闭环，不是"生成完就算"。
  • 净室 vs 深挖：默认「净室」拒绝读取目标内部（源码/文件），只看外部可观察（截图、可见文字、量出的布局/配色/字体/间距）；切到 Deep 才开放代码/JS/Ghidra。把合规做成产品默认档位。
  • 证据账本：每个结果都是带 confidence / coverage / limitations 的证据记录，大结果先 summary 再用 core_evidence_browse 分页——直接对抗大模型幻觉。
  • 工程化细节：工具即 CLI 子命令又即 MCP 工具（agent-ready）；安装依赖等命令有「审批卡片」闸门；项目目录 craft.json/capture/app/checks/investigation.cany/inbox 可审计可续跑。

3) 横向对比与趋势

本周样本仅 1 个，无法做严格横向对比，但可读出几条方向性信号（供后续周累积验证）： - "看懂→重建"成为独立赛道：不再只是"读代码"，而是把「研究—生成—比对—迭代」做成流水线产品。 - Rust 作为基础设施首选：单文件跨平台、可编译 WASM（浏览器里也能跑一部分）；同类工具（含我们此前用的 REA）也偏 Rust/TypeScript + MCP。 - agent-ready 成标配：同一能力同时暴露 CLI + MCP，让"人用的 App"和"智能体调用"共用一套工具。 - 证据化 / 可审计：结果附带覆盖率与局限，正在从"炫功能"转向"可信、可复现"。 - 合规产品化：净室默认档，比免责声明更有约束力。
