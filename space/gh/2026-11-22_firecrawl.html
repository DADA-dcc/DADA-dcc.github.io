1) 它是干什么的（说白了）

一句话：把任何网页"洗"成 AI 能直接读的干净文本。

网页对 AI 不友好——满屏广告、导航、JavaScript 动态加载。Firecrawl 干的事就是：你给它一个链接，它把整页内容抓下来、去掉垃圾、转成结构化 Markdown，AI 直接就能用。

三种用法（README 原话）： 1. Firecrawl Local：装在自己电脑上，一个可执行文件，不依赖数据库/队列/容器； 2. Firecrawl Cloud：官方托管服务，量大、还带搜索和 550+ 数据源； 3. 自托管：从 apps/api 部署完整服务（带队列、worker、数据库）。

2) 架构：四个核心动作 + 两条路

            ┌──────────── 你/你的 AI ────────────┐
            │                                   │
      Firecrawl Local (本机)            Firecrawl Cloud (托管)
      Rust 单文件，无依赖                firecrawl.dev API
            │                                   │
            └────────── 同一套能力 ─────────────┘
                            │
   ┌──────────┬──────────┬──┴───────┬──────────┐
   Scrape     Crawl      Map        Search     Interact / Agent
   抓一页     抓整站     列全部URL  联网搜索    点按操作 / 自主采集
  • Scrape：抓单个页面 → Markdown；
  • Crawl：抓整站，按页存文件；
  • Map：只列站点所有 URL（不抓内容，快）；
  • Search：联网搜索（Cloud 能力）；
  • Interact / Agent：抓完还能"点按钮、翻页"，甚至自主采集。

3) 核心机制（怎么做到的）

A. 真浏览器渲染 - 需要 JS 的页面，用你机器上已有的 Chrome/Chromium 渲染；没有浏览器时，纯静态页也能抓，但会提示"这页需要浏览器"。 - PDF、Office 文档也能在本地解析。

B. 输出以 Markdown 为主 - 默认给 Markdown（干净、带结构），也支持结构化 JSON（Cloud）。

C. 两种接入方式 1. 命令行： bash firecrawl-local scrape https://example.com --markdown firecrawl-local crawl https://docs.example.com --limit 50 --out ./pages firecrawl-local map https://example.com 2. 本地 API 服务： bash firecrawl-local serve # 在 3002 端口提供 Firecrawl v2 API，本地不需要 key 现有 Firecrawl SDK 改个地址就能用：Firecrawl(api_url="http://localhost:3002")。

D. 一键接进 AI 工具（关键）

firecrawl-local init

它会自动找到你机器上的 Claude Code / Claude Desktop / Cursor / Windsurf / Gemini CLI / Codex，把 Firecrawl Local 注册成 MCP server，并且先备份每个配置文件（需要 Node.js 22+，注册后重启 AI 工具生效）。

4) 一次完整使用（走一遍）

  1. 装（需要 Rust 环境）： bash cargo install firecrawl-local 没有 Rust 也可以先用云端：npx -y firecrawl-cli@latest scrape https://firecrawl.dev
  2. 抓一页看效果： bash firecrawl-local scrape https://firecrawl.dev --markdown
  3. 抓整站存 Markdown： bash firecrawl-local crawl https://docs.firecrawl.dev --limit 50 --out ./pages
  4. 接进 AI：firecrawl-local init → 重启 AI 工具 → 之后 AI 就能自己"抓网页"。

5) 它比同类强在哪

  1. 本机就能跑：Rust 单文件，不用 Docker、不用数据库，隐私页面不出本机；
  2. MCP 一键注册：自动识别 6 种主流 AI 客户端并写配置（还先备份），省掉手写 mcp.json；
  3. 复用本机浏览器：用已有的 Chrome/Chromium 渲染，不额外下载浏览器；
  4. 同一套 API 本地/云端通用：本地写的代码迁到云端不用改；
  5. 生态成熟：206k star、多语言 SDK（Python/Node/cURL/CLI）、文档齐全。

6) 怎么用在你身上（对 DSH 的具体价值）

场景 用法
查资料（Google/维基/知网/学术） 页面是 JS 重灾区，用 scrape 拿到干净正文再分析，比直接抓 HTML 准
知网/学术页 只能拿摘要时，用 crawl 批量抓多篇摘要做对比
接进 DSH firecrawl-local init 若支持 Codex/Claude 配置路径，可参照其生成的 MCP 配置手工接入 DSH
离线留存 crawl --out ./pages 把整站存成本地 Markdown，进你的记忆库（chroma）做检索
