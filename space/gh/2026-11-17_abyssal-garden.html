1) 它是干什么的（说白了）

一个打开网页就能"潜水"的海底世界，而且整个世界的画面没有任何图片、模型、音频文件——全是代码现场算出来的。

就像有人给你一个 96KB 的小盒子（比一张手机照片还小），打开后里面有：摇摆的海带森林、从水面射下来的光柱、沉船、鲸鱼尾巴、蝠鲼、鱼群、气泡，还有现场合成的海底音效。

它解决的问题：证明"一个网页 + 一块显卡"就能做出接近游戏画面的 3D 世界，不需要美术素材、不需要游戏引擎、不需要安装。

2) 它由哪几块组成（像一个小剧组）

index.html（96KB，一个文件 = 整部片子）
 ├─ 场景组（world.js）：地形、海带、沉船、鲸鱼尾、鱼群怎么摆
 ├─ 灯光组（shaders.js）：水色、雾、光柱、水面波纹怎么算
 │    ↑ 用 WGSL 写"着色器"——告诉显卡每个像素怎么上色
 ├─ 导演组（main.js）：摄像机、WASD 控制、6 个观景点、画质调度
 ├─ 音效组（audio.js）：用 Web Audio 现场合成深海轰鸣/鲸叫/气泡
 └─ 质检组（quality.js）：按你的电脑自动选"低/中/高"画质

关键点：没有 3D 引擎（Unity/Three.js 都没有），直接调用浏览器的 WebGPU（显卡接口）。所有形状都是数学公式拼出来的——球、圆柱、噪声函数。

3) 核心机制（它是怎么做到的）

A. 海底不是"画"出来的，是"算"出来的 - 页面一打开，显卡用噪声函数（一种"随机但有规律"的数学）把海底、岩壁、拱门"雕"出来； - 然后撒上约 200 万片海带叶子、几万块石头、几千个珊瑚和海绵——位置都是程序生成的。

B. 光柱和焦散怎么来的 - 不是贴图，是着色器里算的：光从水面往下、按水深变暗、加雾、加波纹； - 所以你游到哪，光就跟着正确变化。

C. 声音也是"算"的 - 没有 mp3，用 Web Audio 现场合成：低频轰鸣、远处的鲸叫、随机气泡声。

D. 怎么保证不卡 - 先测你的设备，自动选 低/中/高； - 运行时如果帧率不够，就先降分辨率、再降低远处的绘制距离，一步一步来； - 开场菜单背后其实已经在跑这个场景（模糊的），所以等你点"下水"时，参数已经调好了。

4) 一次完整体验（像进游乐园）

  1. 用 Chrome/Edge 打开 index.html（需要支持 WebGPU 的浏览器）；
  2. 等几秒，世界在你显卡上"长"出来；
  3. 点 Dive in → 鼠标看方向，WASD 游，E/Q 上下，Shift 加速；
  4. 按 1–6 直接跳到 6 个观景点（沉船、海带森林、光柱、紫色洞窟…）；
  5. 按 M 开关声音，H 看帧率，Esc 打开菜单换画质。

5) 它比同类强在哪

  1. 体积极小：96KB 一个文件，离线也能跑，随手发微信都行；
  2. 零素材：没有图片/模型/音频版权问题，全是代码；
  3. 不用引擎：直接 WebGPU，性能上限高（RTX 5070 Ti 上 2560×1440 约 180 帧）；
  4. 自适应画质：从 8GB 手机到高端显卡都能跑，低端机 20 帧也能玩；
  5. 源码可读：source/src/ 分模块写得清楚，适合学习"程序化生成"。

6) 你可以怎么玩

  • 只想看：下载 index.html 双击打开（Chrome/Edge），或直接开在线版；
  • 想改：装 Node.js 18+，然后： bash cd source && npm install && npm run build 想改水色就搜 WCOL，想改游泳速度就搜 26 : 7（快 : 慢）。

给你的建议：先玩 5 分钟，再去 world.js 改一个数字（比如海带数量），重新 build——这是理解"程序化世界"最快的方式。

7) 一句话总结

Abyssal Garden = 96KB 代码 + 一块显卡 = 一整个海底世界：没有素材、没有引擎，全靠数学和着色器现场生成，还自动适配你的设备。
