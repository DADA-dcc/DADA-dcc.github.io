1) 它是干什么的（说白了）

帮你把一个"老项目"一块一块改写成 Rust，而且每改一块都要"对答案"，确认没改坏。

就像装修老房子：不是一上来全砸了重来，而是先量好每个房间的尺寸、拍下水电位置，然后一间一间改；每改完一间，就拿卷尺去量——和原来的尺寸对得上，才继续下一间。

它解决的问题：把老语言（TypeScript、Python、Go…）迁到 Rust 通常很危险——改着改着行为就变了。这个工具把"搬家 + 验收"做成了流水线。

2) 它由哪几块组成（像一支装修队）

┌─ 测量员 profile：先看哪里最慢、谁在调用它
├─ 规划师 analyze：先搬哪块、按什么顺序、有什么风险
├─ 造桥工 bridge：搭一座"桥"，让老代码还能照原样调用新 Rust
├─ 录像机 record：把老程序对各种输入的反应录下来（cases.jsonl）
├─ 验收员 diff：拿录像逐条回放，新 Rust 必须一模一样
├─ 计时员 bench：到底快了多少？值不值得上线
├─ 影子 shadow：新旧同时跑，先返回老结果，偷偷比对
└─ 门禁 gate：格式/静态检查/测试/不许有未完成项，全过才算完工

关键：它不替你翻译代码。翻译由你（或你的 AI 编程助手）写，它负责"指路 + 出题 + 判卷"。

3) 核心机制（它是怎么做到的）

A. 先"录像"，再"对答案" - record 会用一堆刁钻输入（emoji、-0、NaN、超大整数、乱序 map…）去跑老程序，把它返回什么、报什么错全存下来； - 你写完 Rust 后，diff 把这些输入原样再喂给 Rust，逐条比对。 - 说白了：先拍下"标准答案"，再拿你的答案去对；对不上就不许往下走。

B. "桥"让老代码无感切换 - bridge 生成一座桥（不同语言用不同技术），老代码还是 import 原来的函数名，实际已经在跑 Rust； - 所以调用方一行都不用改。

C. 为什么"小函数用 Rust 反而更慢" - 每次调用都要"过桥"（跨语言），过桥费比干活还贵； - 它的解法是 --batch：把"一万条数据"一次性搬进 Rust，在 Rust 里用多核跑完再搬回来——过桥一次，干一万次活。 - 这就是 README 里"20 倍加速"的来源：不是函数快，是把整个循环搬过去了。

D. 只有全绿才算完 - gate 会检查：格式、静态检查、测试、有没有没搬完的、错误路径是否都录过、有没有乱用 unwrap； - 还会比对代码行数——Rust 版不能比原版膨胀 3 倍以上（防手写重复造轮子）。

4) 一次完整流程（像装修验收）

  1. profile：跑一遍真实负载，告诉你"时间花在哪个函数、谁在调它"；
  2. analyze：给出搬迁顺序、风险点（比如字符串编码差异、正则不兼容）；
  3. bridge：生成 Rust 骨架 + 桥；
  4. record：录下老程序的行为；
  5. 你/助手写 port.rs；
  6. diff → bench → shadow（线上影子跑）→ gate；
  7. 全部通过，这块就算搬完，继续下一块。

5) 它比同类强在哪

  1. 不靠"猜"：每一步都有录像做证据，不通过就不让走；
  2. 承认 Rust 不一定快：小函数过桥反而慢，它用 bench 给你结论，用 --batch 解决；
  3. 敢于说"抓不到"：README 专门写了"它抓不到什么"（没录到的输入、正则差异、浮点格式、其他平台）——这种诚实很少见；
  4. 面向 Agent 设计：setup 直接把 MCP 工具和技能装进 Claude Code/Codex/Cursor/Gemini CLI；
  5. 真实数据：6 种语言、38,251 条用例、0 不匹配；Go 的 path、Ruby 的 shellwords 等真实代码都搬过。

6) 你可以怎么玩

cargo install rust-anything
rust-anything setup      # 注册到 Claude Code / Codex / Cursor / Gemini CLI

然后对你的 AI 助手说一句：

"用 rust-anything 把这个 CLI 逐块改写成 Rust，并证明行为一致。"

给你的建议：如果你有个"跑得慢但不敢动"的 Python/TS 小工具，先用 profile 看热点，再只搬那一个循环——这是风险最低、收益最明显的用法。

7) 一句话总结

rust-anything = 给"老项目改 Rust"配了一套"录像 + 对答案 + 门禁"的流水线：不替你翻译，但保证你每搬一块都不走样。
