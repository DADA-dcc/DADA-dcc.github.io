一句话先说明它怎么优化你的 DSH 工作：它演示了"一套技能怎么打包成可被多个 AI 编码工具（Codex / Claude Code / Cursor / Gemini CLI）通用安装的插件"，正好是给 DSH 扩技能、做技能分发时能照抄的目录结构和清单格式。

1) 项目是什么 / 解决什么问题

说白了就是： 一套"教 AI 画 UI 设计稿、并把设计稿变成前端代码"的技能包，只不过它是用"技能（Skill）"这种文件形式组织的。

它是 Google Labs 给自家的 Stitch（一个 AI 生成 UI 界面的工具）配的"操作手册集合"。AI 编码助手装上这些手册后，就知道该怎么一步步调用 Stitch 的接口去：把代码变成设计稿、用一句话生成界面、改界面、导出设计规范、再把设计稿转成 React / React Native / shadcn-ui 组件。

  • 解决什么问题：AI 助手"会写代码但不会用 Stitch"——它不知道 Stitch 有哪些能力、先后顺序是什么。这套技能就是"操作说明书 + 提示词模板"。
  • 规模：3 个插件（design / build / utilities），共 16 个技能。
  • 兼容：Codex、Claude Code、Cursor、Gemini CLI、Antigravity、OpenCode。

2) 整体架构与模块划分（文字架构图）

说白了就是： 一个大盒子按"干什么"分三个抽屉，每个抽屉里放若干个"小册子（SKILL.md）"，外面再放一张"目录牌（marketplace.json）"告诉 AI 去哪找。

stitch-skills/
├── .agents/plugins/marketplace.json     ← 目录牌：列出 3 个插件，告诉 Codex 怎么装
├── plugins/
│   ├── stitch-design/                   ← 抽屉①：设计（画稿）
│   │   ├── plugin.json                  ← 这个抽屉的"身份证"（名字/版本/作者/关键词）
│   │   ├── .codex-plugin/               ← Codex 专用的安装信息
│   │   └── skills/
│   │       ├── generate-design/SKILL.md     一句话生成/改界面
│   │       ├── code-to-design/SKILL.md      代码→设计稿
│   │       ├── manage-design-system/        设计系统（颜色/字体/圆角）
│   │       ├── extract-design-md/           从源码抽出 DESIGN.md
│   │       ├── extract-static-html/         抓取网页存成静态 HTML
│   │       └── upload-to-stitch/            上传本地素材
│   ├── stitch-build/                    ← 抽屉②：出码（设计→代码）
│   │   └── skills/{react-components, react-native, remotion, shadcn-ui, react-vite-dashboard}
│   └── stitch-utilities/                ← 抽屉③：杂务（提词/规范/循环）
│       └── skills/{design-md, enhance-prompt, site-md, stitch-loop, taste-design}
└── README.md / CONTRIBUTING.md / LICENSE / SECURITY.md

关键设计：每个技能是一个文件夹 + 一个 SKILL.md；能力的"身份证"（plugin.json）和"目录牌"（marketplace.json）是分开的两层。

3) 核心机制与关键代码

机制一：靠"清单文件"让不同 AI 工具都能装

说白了就是： 同一个技能包，写一张"目录牌"，Codex 看这张牌就知道去哪拿；Claude Code / Cursor 用 npx plugins add 也能读同一张牌。

.agents/plugins/marketplace.json（节选，真实内容）：

{
  "name": "stitch-skills",
  "plugins": [
    { "name": "stitch-design",
      "source": { "source": "local", "path": "./plugins/stitch-design" },
      "policy": { "installation": "AVAILABLE", "authentication": "ON_INSTALL" },
      "category": "Productivity" }
  ]
}

这行在干嘛：source.local.path 指向插件文件夹；authentication: ON_INSTALL 表示"安装时再做登录认证"。

机制二：技能文件用 frontmatter 声明"我能用什么工具"

说白了就是： 每个 SKILL.md 开头有一段"元信息"，写明这个技能允许 AI 用哪些工具（避免它乱调）。

plugins/stitch-design/skills/generate-design/SKILL.md（真实抬头）：

---
name: stitch::generate-design
description: >-
  Generate new screens from text prompts or images, edit existing screens ...
allowed-tools:
  - "stitch*:*"     # 允许调用所有 Stitch MCP 工具
  - "Bash"
  - "Read"
  - "Write"
  - "web_fetch"
---

这行在干嘛：allowed-tools 是"能力白名单"——只准用这些，别的一律不行。

机制三：生成前强制"先想清楚再动手"

generate-design 里规定：调用任何生成工具之前，必须先跑一遍"提词增强流水线"： 1. 先用 list_projects 找到项目 id（没有就 create_project）； 2. 用 list_design_systems 看有没有设计系统——有，就绝不再在提示词里写颜色/字体（直接用项目级的）；没有，先交给 manage-design-system 技能建一个； 3. 然后再把用户的模糊需求"翻译"成专业 UI/UX 措辞，才去生成。

4) 数据流 / 调用时序（一步步走一遍）

以"给我做一个约会 App 的浏览页"为例：

  1. 用户对 AI 说需求 → AI 发现这属于 generate-design 技能的范围，自动加载这个 SKILL.md；
  2. AI 按说明书，先调 stitch.list_projects 拿项目列表 → 选定 projectId；
  3. 调 stitch.list_design_systems → 看有没有现成设计令牌；
  4. 走"提词增强"：把"做一个约会 App 浏览页"改写成带 UI/UX 术语的详细描述；
  5. 调 stitch.generate_screen_from_text（带 projectId + 增强后的提示词）→ 得到设计稿；
  6. 若要变体：调 stitch.edit_screens / 生成 3 个变体；
  7. 想变成代码：切到 stitch-build 抽屉里的 react-components 技能，把设计稿转成 React 组件。

另一个亮点是 stitch-loop（接力棒循环）： - 每一轮从 .stitch/next-prompt.md（接力棒）读出"这一轮要建哪一页"； - 用 Stitch 生成这一页 → 整合进站点； - 再把"下一页要做什么"写回接力棒文件，交给下一轮。

说白了：像接力赛传棒，AI 可以自己一棒一棒把整个网站建出来，不靠人盯着。

5) 关键难点与巧思（它比同类强在哪）

  1. 一套内容、多工具通用：靠 marketplace.json + plugin.json 两层清单，Codex / Claude / Cursor / OpenCode 都能装，不用维护多套。
  2. 能力白名单（allowed-tools）：技能声明自己能碰哪些工具，降低"AI 乱调工具"的风险——这跟你 DSH 里给插件限定工具是一个思路。
  3. "设计系统优先"的约束：一旦项目有设计令牌，就禁止在提示词里重复写颜色字体，保证界面风格统一。
  4. 接力棒循环（baton）：用三个小文件（next-prompt.md / DESIGN.md / SITE.md）把"多轮自动建站"变成可续跑的状态机。
  5. 命名空间：技能名用 stitch::generate-design 这种前缀，避免和别的技能撞名（但 OpenCode 要求 kebab-case，得改名——作者在 README 里专门提醒了）。

6) 如何自己复现 / 上手

前提：得先有 Stitch MCP 服务器（Google 的远程 MCP 服务，需要按官方文档拿 MCP URL 和凭证）。

  • Codex（最省事，走插件市场）： bash codex plugin marketplace add google-labs-code/stitch-skills --ref main \ --sparse .agents/plugins --sparse plugins/stitch-design --sparse plugins/stitch-build --sparse plugins/stitch-utilities
  • Claude Code / Cursor： bash npx plugins add google-labs-code/stitch-skills --scope project --target claude-code npx plugins add google-labs-code/stitch-skills --scope workspace --target cursor
  • 只挑技能：npx skills add google-labs-code/stitch-skills
  • 最小示例：装好后直接对 AI 说"用 Stitch 生成一个设置页，套用我们的 DESIGN.md"，它会自动选到 generate-design。

7) 一句话总结

它就是"把 AI 用 Stitch 画 UI、出代码"的完整操作手册，用"插件清单 + 带 allowed-tools 的 SKILL.md + 接力棒循环"三层结构打包，能被多种 AI 编码工具通用安装——是给 DSH 做技能包/插件分发时最好的抄结构样本。

你可以怎么玩 / 试一下：不用真接 Stitch，先把它 plugins/stitch-utilities/skills/stitch-loop/SKILL.md 打开抄那段"接力棒"设计，套到你自己的长任务上——让 DSH 每轮读一个 next-prompt.md 干活、再写下一轮任务，长任务就能自动接着跑。

与你项目的适配度（固定段）

  • 对 DSH 的具体用法：
  • 抄它的目录结构：plugins/<插件>/plugin.json + plugins/<插件>/skills/<技能>/SKILL.md，正好和你 ~/.dsh/skills/ 的单层结构互补——可以升级成"技能包（bundle）"形态；
  • 抄 frontmatter 的 allowed-tools 字段，给 DSH 技能加"能力白名单"（我们现在没有这个字段，加上能减少乱调工具）；
  • 抄 marketplace.json 清单格式，做你自己的"DSH 技能市场"；
  • 抄 stitch-loop 接力棒，做一个 DSH 版的"长任务续跑"技能（配合你已有的定时任务/记忆库）。
